# B14 Excel 自有台账双向互转

本文说明「导出 → Excel 编辑 → 导回 → 预览合并」的回合制同步。对应 bead
`te-h7l.25`。实时双写同一个 Excel 文件明确不在范围内。

## 设计原则

- **回合制**：用户显式导出、编辑、导回；系统只在「确认导入」时落库。
- **列 = 当前字段定义**：台账和空白模板的列都由当前启用的合同字段直接生成，
  不再按 `in_ledger` 过滤，也没有「导出哪些列」的配置。应用内台账表格仍按
  `in_ledger` 显示。运行时新增字段后重新导出即包含新列，导回自动识别。
- **不静默覆盖**：系统在导出后发生的改动会让对应行变成冲突，必须逐行选择
  「保留系统 / 采用 Excel」。
- **删除显式确认**：Excel 里删掉的行默认只作为「删除候选」展示，勾选「应用删除」
  才真正删除。
- **资产不进 Excel**：签名、公章等图片仍以数据目录内的资产文件保存；Excel 只承载
  结构化字段，签名/公章资产与签名状态仍在系统内，不嵌入图片二进制。

## 导出文件结构

`GET /app/api/v1/excel/ledger`（可按 year/status/q 过滤）生成的工作簿：

| 位置 | 内容 |
| --- | --- |
| `合同台账` 工作表 | 一列一个当前启用字段，顺序由字段排序决定；数值/金额保持数值单元格 |
| `合同台账` 最后一列 `_合同ID` | **隐藏**技术列，写入稳定合同 id；用于在合同编号被编辑后仍匹配原记录 |
| `_腾手快照` 工作表 | **隐藏**快照表，记录快照版本、导出时间、字段键列表，以及每行 `[合同ID, 合同编号, 行指纹]` |

`_腾手快照` 不要删除或修改。没有快照的文件按「外部/旧版文件」处理：只做普通的
新增/更新合并，不识别删除与冲突。读取时会跳过所有以 `_腾手` 开头的工作表，
不会把技术表误当成数据表。

### 行指纹

行指纹 = 该行在快照字段键列表上的全部导出值，按字段 key 排序后拼接的 SHA-256。
数值/金额会先归一化（去掉千分位、统一小数写法），日期归一为 `YYYY-MM-DD`，
是/否归一为「是/否」，因此 Excel 的显示格式变化不会被误判成修改。

导入时对每一行比较三个指纹：

| 快照指纹 | 系统当前指纹 | Excel 当前指纹 | 结论 |
| --- | --- | --- | --- |
| = | = | = | 不变 |
| = | = | ≠ | 更新（只有 Excel 改了） |
| = | ≠ | = | 冲突：系统在导出后修改 |
| = | ≠ | ≠ | 冲突：两边都修改了 |
| 有该行快照但系统记录不存在 | — | — | 冲突：系统在导出后删除 |
| 系统中存在但快照无此行 | — | — | 冲突：系统在导出后新建 |
| 快照有、Excel 无 | — | — | 删除候选（默认不执行） |

如果导出后有字段被删除或归档，旧文件缺少可靠的可比列，预览会明确提示并建议
重新导出后再编辑；这类行的指纹可能对不上，从而显示为冲突（默认保留系统，不会
静默覆盖）。

## 预览动作

`POST /app/api/v1/excel/preview` 返回逐行动作：

- `create`：新增（无匹配记录）；合同编号留空时写入阶段自动分配。
- `update`：更新；空白单元格语义为「保持不变」，非空才覆盖。
- `unchanged`：无变化。
- `error`：校验错误；默认只要有错误行就整批不写入，可勾选「跳过错误行」。
- `conflict`：需要人工选择；返回 `conflict_reason`、`system_values`、`excel_values`
  （只列出有差异的字段）。
- `delete`：导出快照里有、Excel 里已没有对应行；`row` 为 0，`key` 为
  `delete:<contract_id>`。

汇总 `summary` 包含 `total / create / update / unchanged / error / deleted /
conflicts`。`deleted` 是删除候选数，`conflicts` 含文件行冲突和删除冲突。

### 匹配主键

1. 隐藏的 `_合同ID` 列（最稳，编号被编辑也能找到原记录）；
2. 导出快照中记录的合同编号 → contract_id；
3. 当前系统的合同编号（外部文件 / 新增行）。

## 提交

`POST /app/api/v1/excel/commit` 的 `options` 在原有字段外新增：

| 字段 | 说明 |
| --- | --- |
| `file_name` | 上传文件名，写入导入审计 |
| `apply_deletes` | 是否执行删除候选；默认 `false` |
| `resolutions` | 冲突处理：`{ "<row key>": "keep_system" \| "use_excel" }`；文件行 key 为 Excel 行号，删除候选为 `delete:<contract_id>` |

规则：

- 有错误行且未勾选 `skip_errors` → `import_errors`，零写入。
- 有冲突行但缺少 `resolutions` → `conflict_unresolved`（HTTP 422），零写入。
  `apply_deletes=false` 时删除冲突不要求处理。
- 提交删除前会再次校验快照指纹与系统当前一致；不一致则转为冲突、不删除。
- 结果包含 `created / updated / unchanged / errors / deleted / conflicts / skipped`。

### 审计

- 每次成功提交追加 **一条导入级审计**：`entity=import`、`action=import`、
  `entity_id` 为文件 SHA-256，摘要含文件名、工作表、新增/更新/不变/删除/跳过/
  冲突/错误计数与文件 SHA-256。
- 逐行写入复用 `SaveContract` / 删除路径，摘要带「Excel 导入：」前缀，操作者沿用
  当前 `operator`（MCP 发起的写入记为 `tengshou-mcp`）。

## 界面

「合同台账」页的「导入 Excel」弹窗：

1. 列映射 + 汇总徽标（新增/更新/不变/删除/冲突/错误）；
2. 冲突区：逐行展示「系统当前 vs Excel」对照表，单选「保留系统 / 采用 Excel」，
   默认保留系统；
3. 删除候选区：列出快照中存在、Excel 中缺失的合同；「应用删除」默认不勾选；
   系统有改动的删除候选同样展示单选；
4. 主表列出新增/更新/不变/错误行；
5. 确认导入后 toast 显示新增/更新/删除/跳过数量。
