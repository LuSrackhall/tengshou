# 续签与相对方档案复用（B7）

B7 解决的是「长期合作方每年重签一次」的重复录入：相对方信息录一次，续签时
自动带出上一份合同的信息，用户确认、修改后保存为新的草稿合同。本版本只做
**第一层（相对方档案复用）** 与 **第二层（用档案 / 旧合同生成新合同草稿）**。
第三层「用留存签名直接签」在 v0.2 按 D3=B 修订为**档案复用**：档案签名可以
直接套印到新合同，不再逐份确认，签署事实与授权范围由出租方用户自行确认。

## 1. D3 边界（v0.2 修订）

D3 把「乙方档案与直接签订」拆成三层：

| 层 | 做什么 | 本版本 |
| --- | --- | --- |
| 一、相对方档案 | 名称、证件号、电话、地址、自定义字段录一次，以后不重填 | 提供 |
| 二、用档案生成新合同 | 把合同内容填成新草稿，用户确认后走正常流程 | 提供 |
| 三、使用档案签名套印 | 档案里的长期签名直接套印到新合同（档案复用） | 提供（v0.2 D3=B） |

第三层不是静默复用：出租方用户在签名对话框明确点击「使用租户档案签名」才会
写入一条 `source=archive` 的签名记录，并记入变更记录与生成记录的签名来源；
签名不绑定合同内容版本，合同内容修改后仍可直接套印，签署事实由用户自行确认。
因此本版本仍然没有「后台自动把旧签名贴到新内容」的路径：

- 续签只生成可编辑草稿，不复制来源合同的签名、公章或已生成的 PDF；
- 新内容合同生成 PDF 前必须按 B4 预检，缺签名返回 `missing_signature`，此时可
  现场扫码手写，或使用档案签名（如档案已有长期签名）；
- 现场手写签名采集后合同内容发生变化，仍按 B4 返回 `content_changed`，需要
  重新采集或走显式确认；档案复用不绑定内容版本，不受此限；
- 界面与文档措辞使用「续签」「生成合同」「套用模板」「档案复用」，不使用
  「直接签订」「在线签约」「代签」等签约平台措辞；不承诺法律效力。

## 2. 两条入口

1. **合同详情「续签」**：在合同表单底部点「续签」，服务端返回续签草稿，新建
   表单预填后可改；保存后新合同记录来源合同，详情横幅可跳转回来源合同。
2. **相对方档案**：
   - 档案行「以此档案新建合同」：只预填乙方档案，不复制任何旧合同内容，
     模板与动态字段由用户选择；
   - 档案表单「历史合同」：按 `party_id` 列出该相对方参与（甲方或乙方）的合同，
     可查看或直接发起续签。

## 3. 预填与清空规则

续签草稿（`service.RenewalDraft`）的规则：

| 字段 | 续签草稿 |
| --- | --- |
| 合同名称、合同类型 | 复制 |
| 甲方、乙方 | 复制（关联档案） |
| 租赁房产 | 复制（同一套房产续签） |
| 模板 | 复制（仍可在保存前由调用方调整） |
| 金额 | 复制 |
| 动态字段 `data` | 全量复制 |
| 合同编号 | 清空，保存时按当前年度自动分配 |
| 年度 | 当前年度 |
| 签订日期、生效日期、到期日期 | 清空 |
| 租赁起止日 | 清空，按新租期重新约定（表单默认一年） |
| 状态 | 重置为草稿 |
| `source_contract_id` | 记录来源合同 |
| 签名、公章、输出文档 | **不复制** |

服务端返回 `reused` 字段清单，界面据此提示带出了多少项信息。

## 4. 溯源记录

- `contracts.source_contract_id`（迁移 0008）记录续签来源。该列**只在创建时
  写入**，更新合同不会修改它；来源合同必须存在，否则返回 `not_found`。
- 溯源是元数据，**不进入 `ContentSHA256`**：仅增加来源链接不会改变合同内容
  指纹，因此不会让已有签名被误判为 `content_changed`。
- 创建续签合同会在变更记录中写入摘要前缀
  `续签（来源 <来源合同编号>）：新建合同 <新编号>「<名称>」`，同时保留操作者与
  时间；合同详情可查看该记录并跳转来源合同。
- 来源合同被删除后，已创建合同的来源编号仍保留，界面提示来源已不存在。

## 5. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/app/api/v1/contracts/{id}/renewal-draft` | 返回 `{source, input, reused}`；`input` 为预填的 `ContractInput` |
| POST | `/app/api/v1/contracts` | 接受 `source_contract_id`（仅创建时生效） |
| GET | `/app/api/v1/contracts?party_id=<id>` | 按相对方过滤（甲方或乙方引用），供档案页列历史合同 |

只读数据接口 `/api/v1/contracts` 同样支持 `party_id`。

## 6. 测试

- 迁移 v7 → v8：旧数据保留，新列默认空；新列创建后往返读写。
- 服务层：续签预填 / 清空规则、来源校验、更新忽略来源、变更记录摘要。
- 安全回归：续签合同不携带来源合同的签名；预检需要新签名
  （`needs_signature`）。
- HTTP：草稿端点、带来源创建、`party_id` 过滤。
- 措辞测试：web 资源、README、docs 中不出现签约平台措辞（本文件除外）。
