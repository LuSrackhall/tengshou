# B8 首装引导与模板向导（H3 防线）

首次使用腾手时，界面从「我有一份上级模板」开始，而不是从空白功能开始。
引导把「导入模板 → 标定位置 → 样例预览 → 试生成 → 录入第一份合同」串成
五步，并在同一个页面给出本机自检与模板体检。引导只做提示与校验，不改动
既有模板、台账与生成流程。

配套决策：`02-问题定义.md` S11「首次使用门槛」「改错模板后果」；
`03-剖析.md` H3 四道闸门第一道。

## 首次启动的判定

- **首次使用**：数据目录里既没有 PDF 模板，也没有合同。已有字段定义
  不影响判定，空数据目录导入旧配置也不会被误判为新用户之外的状态。
- 引导状态保存在 `config.json` 的 `onboarding` 对象中（0600、原子写入，
  沿用 `config.Settings` 的保存方式）：
  - `completed` / `completed_at`：完成引导的时间；
  - `skipped` / `skipped_at`：跳过引导的时间；
  - `steps`：样例预览与试生成这两个「不产生业务数据」的步骤的完成时间。
- 完成或跳过后不再自动切到引导页；顶部导航的「新手引导」始终保留，
  可随时手动重开（`reopen`）。

## 五步路径

| 步骤 | 判定方式 | 点击后 |
| --- | --- | --- |
| ① 导入上级模板 | 存在任一 PDF 模板 | 打开「模板」页并弹出导入对话框 |
| ② 标定字段、签名与公章位置 | 存在已标定位置的模板 | 打开该模板的标定编辑器 |
| ③ 用样例数据预览 | 引导记录的 `sample_preview` | 打开标定编辑器并自动做样例预览 |
| ④ 试生成 PDF | 引导记录的 `trial_pdf` | 样例预览后在浏览器本地下载 PDF |
| ⑤ 录入第一份合同 | 存在任一合同 | 打开「新建合同」表单 |

第 ③④ 步刻意使用样例数据：它们不需要、也不会在台账里留下任何记录，
因此完成时间只能记录在 `config.json`，而不是数据库。其它步骤每次都从
真实数据重新判定，不会出现「标记完成但实际没做」的状态。

## 试用数据与真实数据的边界

- 样例预览与试生成只走现有的 sample 渲染路径（`PreviewTemplate` 的
  `sample: true`），服务端返回临时 PDF，**不写入** `contracts`、`parties`、
  `templates` 或 `output_documents`。
- 试生成 PDF 由浏览器把内存中的预览保存到本地，不生成生成记录，也没有
  「把样例合同落库」的入口。
- 界面在引导页、样例预览标题和试生成按钮上明确标注
  「样例数据，不写入台账」。
- 首次启动不自动写入任何真实或样例业务数据；不预置地方模板；现有内置
  字段与服务端 demo 数据保持原样。整个引导不访问网络。

## 模板体检

导入模板后，引导页和模板标定页都会显示模板体检结果。它把模板的标定位置
与当前字段定义比对，只读、不修改模板：

- 未知字段绑定（例如旧模板引用已不存在的字段）：错误，提示「去字段页新增，
  或到模板标定页改绑」；
- 已归档字段绑定：提醒生成时该位置为空；
- 必填合同 / 相对方字段没有标定位置：提醒补位置或确认不需要出现在正文；
- 没有签名位置 / 公章位置：提醒按需补充，不需要可忽略；
- 没有任何标定位置或没有字段位置：提示先完成标定。

## 本机自检

`GET /app/api/v1/onboarding/check` 逐项返回
`{id, label, status: ok|warn|error, detail, action, target}`，右侧面板按
状态显示「通过 / 需留意 / 需处理」，需要处理的项给出下一步与可跳转的页面。

| id | 检查内容 | 失败时的下一步 |
| --- | --- | --- |
| `data_dir` | 数据目录可写 | 检查目录权限，或换到可写位置 |
| `database` | SQLite schema 版本与完整性 | 重新打开腾手；必要时从备份恢复 |
| `converter` | Word 转换：Windows 报 Microsoft Word（COM），其它平台报 LibreOffice | 安装 LibreOffice，或用 Word / WPS 另存为 PDF 后直接导入 |
| `signature_lan` | `http.allow_lan` 与可用局域网地址 | 开启 allow_lan 并重启；连接 Wi-Fi / 网线 |
| `fields` | 合同 / 相对方字段定义可读 | 重新打开腾手 |
| `template` | 模板数量与当前版本标定 | 去「模板」页导入或标定 |
| `sample` | 中文字体与样例生成就绪度 | 安装中文字体，或在 `config.json` 设置 `pdf.font_path` |
| `backup` | 最近备份文件或最近一次备份导出 | 去「数据安全」页导出完整备份包 |
| `disk` | 数据目录所在磁盘剩余空间 | 清理磁盘，或把数据目录移到更大的磁盘 |

## 常见失败与处理

- **导入 .docx 时提示转换程序不可用**：安装免费的 LibreOffice，或用
  Word / WPS 把模板另存为 PDF 后直接导入 PDF；导入 PDF 不依赖转换程序。
- **样例预览或试生成提示找不到中文字体**：安装中文字体，或在
  `config.json` 的 `pdf.font_path` 指定字体文件后重新打开腾手。
- **模板体检提示未知字段**：该位置引用的字段已不存在。去「字段」页新增
  同名字段，或到模板标定页把位置改绑到已有字段；体检不会自动改动模板。
- **模板体检提示缺必填字段 / 签名 / 公章位置**：按提示到模板标定页补位置；
  签名和公章位置确实不需要时可以忽略提醒。
- **手机扫码签名打不开**：确认 `http.allow_lan=true` 并重启腾手，手机与
  电脑在同一局域网；自检会列出可用局域网地址。
- **自检提示数据库版本不一致**：重新打开腾手完成升级；升级前先在
  「数据安全」页导出备份。完整性检查失败时优先从备份恢复。
- **自检提示没有备份**：导出一次完整备份包并像合同原件一样保管；备份包
  未加密，包含签名与公章图片。
- **自检提示磁盘空间不足**：清理磁盘，或把数据目录迁移到空间更大的磁盘
  （迁移前先导出备份）。

## 接口

均在本机应用写入面（回环 + `X-Tengshou-App: 1`）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/app/api/v1/onboarding` | 首次判定、五步状态与数据事实 |
| GET | `/app/api/v1/onboarding/check` | 只读自检项 |
| POST | `/app/api/v1/onboarding/state` | `complete` / `skip` / `reopen` / `step`（仅 sample_preview、trial_pdf） |
| GET | `/app/api/v1/templates/{id}/check` | 只读模板体检 |

`GET /app/api/v1/bootstrap` 同时返回 `onboarding` 对象，首屏不必额外请求。

## 手动重开

顶部导航「新手引导」始终可见。已完成的引导在页面内点「重新打开引导」即可
重新显示自动提示，并保留已完成的样例步骤记录。

## 措辞边界

界面与文档使用「生成合同」「套用模板」「留存签名」「台账」「字段对齐导出」；
不使用签约平台类措辞，不承诺远程人工服务。措辞由
`internal/httpapi/onboarding_wording_test.go` 覆盖。

## 验收与测试

- 新用户按引导完成第一份模板与第一次试生成；
- 每个失败点有明确提示与下一步，不出现死路；
- 首次生成前有样例预览，用户能看懂「哪里会填什么」；
- 不预置地方模板；不依赖联网。
