# B9 数据安全、备份与恢复

腾手是单机应用：合同数据、签名与公章图片、模板、生成的 PDF 和配置全部在
**本机数据目录**里，不经过任何服务器。本页说明数据在哪、如何备份、如何换机
迁移，以及仍然存在的风险。

## 数据目录

默认位置（可用 `--data-dir` 或 `TENGHSHOU_DATA_DIR` 覆盖）：

| 平台 | 路径 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Tengshou` |
| macOS | `~/Library/Application Support/Tengshou` |
| Linux | `$XDG_DATA_HOME/tengshou` 或 `~/.local/share/tengshou` |

```
<data>/
  config.json     # 端口、API 令牌、字体、页边距、签名有效期、MCP 开关
  tengshou.db     # SQLite 数据库（WAL）
  assets/         # 签名 assets/signatures/、公章 assets/seals/
  templates/      # HTML 模板；PDF 模板 templates/pdf/<模板id>/（source.docx、template.pdf）
  outputs/        # 已生成的 PDF
  backups/        # 完整备份包与恢复前安全副本
  logs/           # 日志，不进入备份包
  fonts/          # 可选中文字体
```

签名和公章图片**不在**任何公开静态目录中：`/app/` 只提供界面代码，图片只能
通过仅回环的 `/app/api/v1` 读取。数据目录权限按最小化处理：目录 `0700`、文件
`0600`（Windows 上 POSIX 权限位作用有限，实际由用户目录 ACL 控制）。

## 一键备份

界面：`/app/` →「数据安全」→「导出完整备份包」。浏览器直接下载
`tengshou-backup-<时间>.zip`，导出动作写入变更记录。

命令行：

```bash
tengshou-cli backup --data-dir ./data
# 完整备份包：./data/backups/tengshou-backup-20260101-090000.zip
```

备份包内容：

| 包内路径 | 内容 |
| --- | --- |
| `manifest.json` | 包格式版本、应用版本、数据库 schema 版本、生成时间、平台、文件清单与每个文件的 SHA-256 |
| `db/tengshou.db` | 用 SQLite `VACUUM INTO` 生成的一致性快照（不是直接拷贝 .db） |
| `config.json` | 用户配置（字段定义、流程、模板映射等配置本身在数据库中） |
| `assets/` | 签名、公章等全部资产 |
| `templates/` | 全部模板文件（含 B3 导入的 Word 源文件与转换后的 PDF） |
| `outputs/` | 已生成的 PDF |

打包不依赖表名或具体文件名：数据库作为一个文件整体快照，资产目录整体遍历，
以后新增的目录或模板子结构会自动包含。日志与备份目录本身不打包。

## 恢复

界面：`/app/` →「数据安全」→「从备份包恢复…」，选择 `.zip` 并确认。

1. 软件先校验包结构、manifest、文件数量与大小、每个文件的 SHA-256，并对
   快照执行 `PRAGMA integrity_check`；任何一步失败都会拒绝，**原数据完全不动**。
2. 校验通过后暂存到 `<data>/.restore/`，界面提示「重启腾手后生效」。
3. 下次启动时，软件自动把当前数据复制到 `backups/pre-restore-<时间>/`
   形成恢复前副本，再整体替换数据库、配置与资产目录。替换失败会自动回滚。
4. 恢复来自更旧 schema 的包时，启动后自动执行数据库迁移；来自更新版本的包
   会被拒绝。

命令行（请先关闭正在运行的腾手）：

```bash
tengshou-cli restore --data-dir ./data --file tengshou-backup-20260101-090000.zip
```

安全限制：

- 拒绝绝对路径、盘符、反斜杠、`..` 穿越、符号链接和白名单之外的顶层目录；
- 限制条目数量与解压后总大小，防止解压炸弹；
- 恢复上传走流式 `multipart/form-data`，不做大包 base64；接口仍强制仅回环、
  Origin 校验与 `X-Tengshou-App: 1`；
- 恢复前安全副本与备份包同级保存，确认无误后可手动删除。

## 换电脑迁移

1. 在旧电脑导出完整备份包，拷贝到新电脑（U 盘 / 移动硬盘）。
2. 新电脑安装并启动一次腾手，让它创建数据目录。
3. 在「数据安全」页选择备份包恢复；重启腾手。
4. 检查合同台账、签名与公章图片、模板和「数据一致性检查」结果。
5. 如新电脑没有原字体，可在 `config.json` 的 `pdf.font_path` 指定本机中文字体。

## 崩溃 / 断电后的检查

- 启动时对数据库执行 `PRAGMA integrity_check`，损坏会直接报错而不会带病运行。
- 启动时比对数据库记录与磁盘文件，报告「有记录无文件」和「有文件无记录」，
  **只报告、不自动删除**。界面中的「数据一致性检查」可随时再次运行。
- 所有写入采用临时文件 + 原子重命名，减少断电留下半截文件的机会。

## 操作审计

以下操作复用既有变更记录（actor 为操作者，MCP 写入标记为 `tengshou-mcp`）：

- 签名导出（每次导出都记录签名、摘要与关联合同）；
- PDF 生成（每份合同一条 `generate` 记录，单份或批量生成都覆盖）；
- 模板导入、标定修改、删除；
- 合同、相对方、公章、模板等数据删除；
- 备份导出、恢复包导入与启动时应用恢复。

## 残余风险（必须知晓）

- **备份包未加密**。包里含合同数据、签名与公章图片、配置（含本机 API 令牌）。
  请像保管合同原件一样保管备份文件，不要放在共享网盘或聊天工具里。
- 恢复需要重启应用；恢复期间请勿运行第二个腾手实例。
- 数据目录的访问控制依赖操作系统账户安全；同一系统账户下的其它程序仍可能
  读取文件。请为电脑设置登录密码并避免共用账户。
- 一致性检查只发现「记录与文件不一致」，不能发现磁盘底层静默损坏；请定期
  导出备份包并离线保存多份。
- `/sign/` 手机签名页仍只允许局域网访问；不要将服务端口映射到公网。
